# PuffFile

**不是要取代檔案總管，而是讓你少走回頭路。**

我們每天在電腦前工作，絕大多數時間都在固定幾個專案或資料夾裡穿梭。PuffFile 專為這種工作節奏而生，採用 Tauri 2（Rust 核心 ＋ WebView2 前端）打造，極度輕盈，只為終結重複導覽的無謂耗損。

## 為什麼要做這個

每天工作時，其實一直在做同一件事：反覆回到某幾個固定的目錄。Windows 檔案總管不是為
這種節奏設計的：

- **容易失焦**：視窗與分頁一多，就很難一眼確認「我現在到底在哪」，也不容易看出焦點
  落在哪個窗格；常用的那幾個工作目錄沒有就手的位置。
- **反覆導覽**：每次都要從磁碟機或側邊欄一層一層點回同一個地方。
- **右鍵選單難用又不能自訂**：項目多、層級深，慣用動作（解壓縮、用 VS Code 開啟、
  在這裡開 PowerShell 7…）掛不上去，只能改登錄檔或裝第三方工具。
- **不能依檔案類型做客製**：例如「只有 .7z／.zip 才出現解壓縮工具」這種規則做不到。

## PuffFile 的解答

* **常駐導覽**：把最核心的工作資料夾釘在最順手的位置，一鍵直達。
* **隨需分割**：分頁與分割窗格隨手可用，比對、整理游刃有餘。
* **情境選單**：依選取的檔案格式自動呈現專屬外部指令，無需再受修改登錄檔之苦。

要搬移整個磁碟、要整理生活相簿，那仍然是原生檔案總管的工作 —— PuffFile 不跟它搶。

**Purpose（設計八原則之 1）＝ 決定「不做什麼」。** 因此明確不做：萬用搜尋、
圖示模式、完整磁碟樹瀏覽、檔案編輯。每一個砍掉的東西，都在替「三秒內回到我的工作資料夾」讓路。

唯一的例外是**檢視器**：Markdown／圖檔／純文字可以在另一個窗格直接看內容，
但它只是窗格的一種暫時內容模式，關掉就回到原本的檔案清單。

## 開發指令

```bash
npm install
npm run tauri dev            # 桌面應用程式（先起 Vite，再編譯 Rust）
npm run dev                  # 只跑前端，瀏覽器預覽模式（自動使用 Mock 資料）
npm run typecheck            # vue-tsc 型別檢查
npm run build                # 型別檢查 + Vite production build
cd src-tauri; cargo test     # 後端單元測試
cd src-tauri; cargo clippy   # 後端 lint
```

打包單檔免安裝版（產出 `dist-portable\PuffFile.exe`，加 `-Zip` 另外產生壓縮檔）：

```powershell
.\build-portable.ps1
```

> **環境需求**：Node `^20.19.0 || >=22.12.0`（Vite 8 的要求）。本專案以 `.node-version`
> 標記 22.23.3，用 fnm／nvm 這類工具會自動切換；Rust 端需要 stable toolchain（edition 2024）。
>
> 如果是在 Node 版本不符的環境安裝，npm 會略過 Rolldown 的 Windows 原生套件，啟動時出現
> `Cannot find native binding`；把 Node 升到需求版本即可。急救用：
>
> ```bash
> npm install @rolldown/binding-win32-x64-msvc --no-save --force
> ```

## 目前功能

### 視窗與版面

- 無邊框 Windows 11 風格外框：標題列＝分頁區｜瀏覽紀錄／設定｜視窗控制鈕，拖曳空白處可移動視窗。
- 分頁：`Ctrl+N`／`Ctrl+W`／`Ctrl+Tab`／`Ctrl+1..9`、中鍵關閉、拖曳排序；關閉最後一個分頁會開一個新的。
- 每個分頁都能左右或上下分割（`Ctrl+\`／`Ctrl+Shift+\`）。兩個窗格各自擁有路徑、選取、
  排序與欄寬；分割方向會記住，下次沿用；分頁／窗格／路徑／版面可設定為啟動時還原。

### 左側：我的資料夾

- 只放工作上常用的資料夾，不列出檔案。工具列的「＋」會先問你要**新增虛擬目錄**（純分組，
  沒有實體路徑）還是**加入真實資料夾**；第一層可以混搭兩者，虛擬目錄裡放真實資料夾（最多兩層）。
- **拖曳節點就能自訂排列順序**，但只在同一層內搬動；要把資料夾搬進虛擬目錄，用它的右鍵選單
  「移動到虛擬目錄…」。虛擬目錄的右鍵選單還有重新命名、加入資料夾到此群組、移除（含內容，
  只從清單移除、不會刪除實體檔案，並提供復原）。
- 工具列的「排序」鈕依名稱排序（A→Z），範圍是**選取項目所在的那一層**：選第一層就排第一層，
  選虛擬目錄裡的資料夾就只排那個虛擬目錄。
- 每個節點能獨立樹狀展開，展開／收合只由節點左邊的箭頭圖示控制；點節點名稱只會選取
  （真實資料夾會一併導覽），不會順手展開或收合。在窗格裡進出資料夾時，左側只跟著高亮、
  不會自動展開；唯一的自動展開是工具列的「定位」——它會跳到目前選取項目所在的資料夾
  （選到檔案就定位它的上層），該目錄不在清單裡時會問你要不要加進來。

### 路徑工具列（每個分頁一條，永遠指向焦點窗格）

- 分割時顯示位置標籤（左／右／上／下），點另一邊時整條列跟著切換。
- 上一頁／下一頁／上一層／重新整理；可點擊的麵包屑，也能直接輸入路徑（`Ctrl+L`）。
- 搜尋目前資料夾（`Ctrl+F`）、在檔案總管中顯示，以及三顆版面切換（一般／左右分割／上下分割）。

### 檔案清單

- 單一條列模式。欄位可自訂（名稱／類型／大小／修改日期／建立日期／屬性／路徑），欄寬可拖曳、
  每個窗格各自獨立、雙擊邊界還原預設值，欄位格線常駐；點欄位標頭排序（資料夾永遠優先）。
- 大量項目採虛擬滾動，只渲染可見範圍。
- 選取：單選、`Ctrl` 多選、`Shift` 連選、`Ctrl+A` 全選、`Esc` 取消、方向鍵移動焦點、
  空白處框選、拖曳到邊緣自動捲動。
- `Space` 把焦點列的項目預覽到另一窗格：資料夾＝開它的檔案清單、支援的檔案＝開檢視器
  （不支援的類型只會顯示提示）。**焦點留在原清單**，方便用方向鍵連續掃描不同項目；
  焦點的檔案已經在另一窗格顯示時，`Space` 會直接前進到下一個能預覽的檔案（跳過資料夾與
  不支援的類型）；資料夾也可以用 `Enter` 直接進入。
- 目錄自動更新（`ReadDirectoryChangesW`）：外部新增／刪除／改名會即時反映，而且不會動到
  你目前的選取與捲軸。

### 檔案操作（與檔案總管互通）

- 剪下／複製／貼上／刪除交給 Windows shell 的 `IFileOperation`：衝突對話框、進度、取消、
  資源回收筒、跨磁碟搬移、長路徑都由系統處理。
- 剪貼簿使用 `CF_HDROP`，可以「在檔案總管複製、在這裡貼上」，反之亦然。
- 分割時可把選取項目複製／移動到另一窗格（僅右鍵選單手動執行，執行前彈窗確認來源與目標）。
- 每一次操作（含失敗與原因）都寫入操作紀錄，設定頁可直接檢視。

### 右鍵選單（依選取情境改變）

| 情境 | 內容 |
| --- | --- |
| 清單空白處 | 在新分頁開啟、建立新資料夾／新檔案、貼上、資料夾類外部工具、複製路徑、在檔案總管中顯示 |
| 單一資料夾 | 開啟、在新分頁開啟、在新窗格開啟、新增、剪下／複製／貼上／刪除、外部工具、送到另一窗格、複製路徑 |
| 單一檔案 | 開啟、在新分頁開啟、（支援的檔案）在新窗格開啟、剪下／複製／刪除、外部工具（再依副檔名篩選）、送到另一窗格、複製路徑 |
| 多選 | 只留下對整組成立的動作；複製路徑會把所有路徑一行一個複製出去（開啟／新增／貼上這種單一目標的動作不出現） |

- 「在新分頁開啟」統一放在選單開頭「開啟」這一組（空白處沒有「開啟」，所以放在最上方）；
  資料夾開啟它自己，檔案則開啟它所在的資料夾。
- 「在新窗格開啟」沿用上次的分割方向，圖示會跟著換；目前分頁已經分割時，這一項改成
  「在左／右／上／下窗格開啟」，直接把內容開到相鄰窗格，不會再開第三個窗格。
- 複製路徑同時提供 Windows（`C:\Users\felix\專案`）與 Linux（`/mnt/c/Users/felix/專案`，
  UNC → `//server/share/...`）兩種格式。

### 檢視器

- 對 Markdown（`.md`／`.markdown`）、HTML（`.html`／`.htm`）、WebView2 能顯示的圖檔，
  以及純文字／程式碼檔按右鍵：
  單一窗格時是「在新窗格開啟」（沿用上次分割的方向），已經分割時是「在左／右／上／下窗格開啟」。
- 檔案清單按 `Space` 走同一條路徑，而且資料夾也適用：資料夾會在另一窗格開成一般檔案清單
  （見「檔案清單」）。
- 開啟後**焦點留在檔案清單**：方向鍵換檔案、再按 `Space` 就更新檢視器內容，可以連續掃過
  同一個資料夾；目前顯示中的那一個再按一次 `Space` 會直接跳到下一個可預覽的檔案，
  要重新載入同一個檔案用檢視器的 `F5`。要對檢視器操作（`Esc` 關閉、`Ctrl+C` 複製選取的文字）
  再點它一下即可。
- 檢視器窗格不會因為不是焦點而被淡化，任何時候都維持正常對比。
- 檢視器佔用該窗格顯示內容，關閉（`Esc`、標頭關閉鈕，或窗格被關掉）就回到同一個資料夾的清單。
- Markdown 支援標題、清單、表格、引用、程式碼區塊、刪除線、連結與圖片；相對路徑的圖片會直接讀取，
  相對連結會回到清單導覽並選取目標。不執行原始 HTML。
- Markdown 檢視器右上角有**目錄索引**浮動面板（預設開啟，開關在檢視器標頭）：依層級列出
  h1～h6、捲動內文時同步高亮目前章節，點項目或內文的 `[文字](#標題)` 都會捲到該行。
  面板可拖曳、可調整寬高（左下角把手，右緣固定）、可收合成只剩標題列，位置與大小會記住；
  最小寬度與底色不透明度在**設定 → 瀏覽 → 檢視器**調整。沒有標題或窗格太窄時面板自動隱藏，
  標頭的開關會反灰停用。
- **搜尋**（Markdown／HTML／純文字與程式碼都有，`Ctrl+F` 或標頭搜尋鈕）：右上角浮動面板，
  同樣可拖曳、可調整寬高、可收合，預設關閉且每個窗格各自獨立。支援大小寫、完整字詞、
  Regex 三個選項（預設全關）、輸入即時搜尋；命中清單顯示「目前索引／總數」與所在行或區塊，
  `Enter`／`Shift+Enter` 上下一個、點一列直接跳，內文同步標示全部命中與目前命中。
  HTML 靜態預覽則直接在 iframe 內的頁面上搜尋。
- HTML 預設是**靜態預覽**：不執行 JavaScript、不載入 http(s) 遠端資源，相對路徑的圖片、
  外部 CSS 與 CSS 內的 `url()`／`@import` 都走 IPC 讀取後內嵌；標頭的切換鈕可以隨時
  改看原始碼。需要 JS 的頁面只會顯示靜態骨架，並在內容上方以提示條說明。
- 圖片以 fit 置中顯示，滾輪縮放、拖曳平移、雙擊在 fit 與實際大小之間切換。
- 純文字等寬顯示並標示偵測到的編碼（UTF-8／UTF-16／Big5／GBK）；程式碼檔（`fileKind.ts`
  的「程式碼」類）與 Markdown 的 ``` 程式碼區塊會語法高亮（highlight.js），顏色跟著深／淺色
  主題走。超過 1 MB 的檔案會跳過高亮並顯示提示，避免卡住畫面。
- 檔案被外部修改時自動重載；刪除後顯示錯誤狀態，可按重試或關閉。

### 外部工具（自訂）

- 每個工具可設定：執行檔、引數（一行一個）、工作目錄、顯示於檔案／資料夾、副檔名篩選（選填）、
  是否開新主控台，以及圖示。
- 副檔名篩選不分大小寫，例如 7-Zip 填 `.7z .zip .rar` 就只會出現在這些檔案上；多選時要整組
  都符合才會出現（選了 `.7z` 加一個 `.txt` 就不會看到它）。
- 引數與工作目錄支援變數：`$fullFilePath`、`$fullFolderPath`、`$fileName`、`$fileStem`、
  `$folderName`，加後綴 `1`／`2` 可取左／上、右／下窗格。多選時，單獨一行的
  `$fullFilePath` 會展開成多個引數（每個選取項目一個）。
- 內建 PowerShell／命令提示字元／Notepad++／VS Code 四個可編輯的範例，執行檔都能改成
  自己慣用的版本（例如 `pwsh.exe`）。

### 瀏覽紀錄與設定

- 全域瀏覽紀錄：上限 100 筆、以正規化路徑去重、新到舊，可即時篩選、單筆刪除、清空。
  分割版面以一筆記錄（兩行路徑＋方向圖示），點一下整組還原。
- 設定頁：主題（淺／深／跟隨系統）、動態效果、顯示隱藏項目、欄位與預設排序、清單自動更新、
  啟動時還原、外部工具編輯、操作紀錄。

### 狀態列與快速鍵

- 狀態列在單窗與分割時排列一致：完整路徑靠左，項目數／已選取資訊靠右；分割時一個窗格一行，
  點一行就能切換到該窗格。
- `F5` 重新整理、`F6` 在窗格之間切換焦點（單窗時切換左側樹）、`Backspace` 上一層、
  `Alt+←`／`Alt+→` 上／下一頁、`Ctrl+F` 搜尋、`Ctrl+L` 輸入路徑、`Ctrl+N`／`Ctrl+W`／
  `Ctrl+Tab`／`Ctrl+1..9` 分頁、`Ctrl+\`／`Ctrl+Shift+\` 分割、`Ctrl+A`／`Ctrl+X`／
  `Ctrl+C`／`Ctrl+V`、`Del` 刪除、`Space` 把焦點列項目預覽到另一窗格（不移焦點；已顯示時改開下一個）、
  `Ctrl+Shift+N` 新增資料夾。
- 完整清單（分頁與版面／導覽／檢視器／選取／剪貼簿與檔案／對話框與浮層）在
  **設定 → 關於 → 快速鍵**，說明文字就在按鍵旁邊。

## 架構重點

- **IPC 隔離**：UI 不直接呼叫 `invoke`，一律經過 `src/services/api.ts`；沒有 Tauri 環境時
  自動降級為 Mock，因此 `npm run dev` 就能在瀏覽器開發 UI。
- **串流列舉**：後端以 Tauri 2 的 `Channel` 分批推送目錄內容（`start` → `batch`* → `done`），
  超大資料夾邊讀邊顯示，換路徑時可以中止過期的請求。
- **統一錯誤處理**：後端 `AppError`（thiserror）序列化為 `{ kind, message, path }`，
  前端以 `normalizeBackendError` 轉成一致的錯誤畫面。
- **狀態單一真實來源**：跨組件狀態集中在 Pinia stores，元件只讀取狀態與觸發 action。
- **平台整合集中在 `core/`**：`core/shell.rs`（IFileOperation、CF_HDROP 剪貼簿）與
  `core/watch.rs`（ReadDirectoryChangesW）都不依賴 Tauri IPC，可獨立測試。
- **純函數工具層**：`utils/` 不依賴 Vue 或 IPC，可獨立測試。

## 後續可做

- **網路磁碟的輪詢備援**：不支援 `ReadDirectoryChangesW` 的位置（部分 SMB／網路磁碟）
  目前會放棄自動更新，只能手動重新整理。
- **左側樹的節點監控與連動**：目前樹是「收合即丟棄快取、展開時重讀」，外部新增資料夾時
  樹要等收合再展開才看得到。
- **樹節點展開／收合的淡入**：其餘動態都已走彈簧，只有這裡還是瞬間出現。
- 更完整的規劃與取捨記錄在 [`docs/redesign-plan.md`](docs/redesign-plan.md)。
